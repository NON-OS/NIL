# Changelog

All notable changes to Nil, the task app made by NØNOS, are listed here, newest first. Versions up to 3.0.0 were released under the NØNOS name.

## Unreleased

### Breaking changes

- `APP_URL` is required. The server refuses to start without it. Wallet sign-in messages and the origin check use it, plus `ALLOWED_ORIGINS`, and never the Host, Origin or X-Forwarded-Host headers. Plain http is accepted only for localhost and .onion addresses. With `npm run dev`, set `APP_URL=http://localhost:5173`. Onion-only servers set it to their .onion address: [docs/tor.md](docs/tor.md) shows the two-step first start.
- `NOX_RPC_URL` is required on a server people reach over the network. There is no public default any more, because a public node sees every address the server looks up. Set your own node, a provider you trust, or `off`. A server whose `APP_URL` is a localhost address still falls back to a public node, with a startup warning.
- `TRUST_PROXY` no longer accepts `true`. Give the proxy's address or subnet (`uniquelocal` for Caddy in the same Compose project, `loopback` for a proxy on the same machine) or a hop count. A value it can't use is ignored with a warning.
- `docker-compose.tor.yml` removes Nil's published port, so an onion-only server no longer answers on its normal IP address.

### Security and privacy

- A phishing site could ask for a sign-in message naming its own domain when `APP_URL` was empty, pass the wallet's domain check and relay the signature to sign in as someone else. Requiring `APP_URL` closes this.
- Guests no longer hear about tasks they can't open. Notifications, mentions, watchers, vote notices, presence and the timesheet export all check who can open the task. Whoever loses access to a task (made private, reassigned, moved out of a guest's projects, a project unshared or deleted) also loses their watch, its notifications and its My Day entry.
- Anonymous ballots are held until the hour they arrived in has ended, then counted together in random order and stored with the hour only, so neither the live count nor the database shows when a ballot came in. Voting keys are registered when a member first unlocks their keys or clicks **Join anonymous votes**, never together with a ballot, and only their owner sees them. The audit file lists ballots by nullifier with hour stamps, and existing ballot and voter-tree times are rounded to the hour (migration 024).
- Signing out closes the live connection that session opened, and live connections close once their session expires or is revoked. Over HTTPS only the `__Host-` session cookie is read, so a cookie planted by a sibling subdomain signs nobody in.
- Pending sign-in challenges are capped per client as well as overall, so one client can't push out everyone else's sign-in. Rate limits and challenges count an IPv6 /64 as one client.
- Private payout balances are read from the Ethereum node one address at a time, at random moments within `STEALTH_BALANCE_SPREAD_SECONDS`, with another payee's address mixed in, and listing payouts no longer calls the node. Vote snapshots read wallets in a shuffled order, a few at a time.
- Wiping the workspace, purging, erasing a person or task, deleting a comment and sealing a task now also clear SQLite's write-ahead log, so deleted text doesn't linger in `nonos.db-wal`.
- Bounty totals leave out private tasks the viewer can't open, admins included.
- The AI draft and deck dialogs say that the text passes through the Nil server on its way to Anthropic. The README lists what the server still knows about a private task.
- `image-size`, which pptxgenjs declares but never loads, is pinned to 2.0.4, past its denial-of-service fixes.
- Anyone can check that a server sends exactly the web app of a release. The build is byte for byte the same on any machine, `npm run release:manifest` writes a manifest of every file with its SHA-256 and the release hash that stands for all of them, and `npm run verify:server -- <address>` compares a running server with your own build or a published manifest: every file, the routes the app opens on, and the Content-Security-Policy. See [docs/verify-a-server.md](docs/verify-a-server.md).
- Private tasks warn when the server sends an older version than this browser has already opened, as docs do. Every save seals the task's words under the next revision number, which the writer's signature covers, so an old version can't be passed off as new. Tasks sealed before this open as revision 0.
- The ballot circuit's phase 2 setup can now run as a real ceremony between people who don't trust each other: `npm run ceremony:start`, `ceremony:contribute` and `ceremony:finish`, with a beacon block announced in advance and the whole chain verified before anything is installed. [circuits/CEREMONY.md](circuits/CEREMONY.md) is the guide for the coordinator and the contributors.

### Encryption keys

These changes follow a security review of the encryption. Keys published before this release can't be checked, so migration 023 removes them, together with the old payout and voting key commitments. Everyone sets up their keys again on their next unlock. See [docs/encryption.md](docs/encryption.md) for the trust model.

Nothing opens what was sealed to the old keys. Docs and private tasks encrypted on 3.0.0 stay locked, and private payouts received on 3.0.0 can't be moved from Nil. Before upgrading, download the docs you want to keep, copy out what you need from private tasks, and move private payouts out or copy their keys. [docs/deploy.md](docs/deploy.md) has the steps.

- Signed key directory with pinning. Publishing or resetting encryption keys needs a fresh EIP-4361 statement signed by one of the person's linked wallets, naming the site, the workspace, the account and both public keys. The server checks it, so a stolen session cookie can no longer replace someone's key. Every browser checks the signature again, pins each teammate's keys the first time it sees them, and seals nothing (docs, private-task keys, trustee shares) to a key until its person confirms the fingerprint. Docs shows when someone new appears with a key or someone's key changes, and Settings, Security lists every teammate's key.
- Keys that don't belong to one wallet. Each person's identity is now a random key made in the browser and stored wrapped once per linked wallet, so any linked wallet unlocks it. An optional recovery kit (scrypt and AES-256-GCM, downloaded as a small file) restores it after an admin links a new wallet. A reset also drops the person's copies of private-task keys, so the task's other holder can hand it over again.
- Key messages are bound to the site. Every message a wallet signs for keys has the EIP-4361 layout and names the site from `APP_URL`, so wallets show the domain and warn on other sites. Private payout and voting keys now come from the identity instead of a separate signature that could be replayed. The browser refuses to sign any sign-in or ballot message from the server that looks like a key message.
- Trustee key setup can't be steered. Trustees of an encrypted vote commit to their dealings before anyone reveals, and each reveal carries a Schnorr proof of knowledge for every commitment, checked by the server and by browsers. Voters rebuild the vote key from the trustees' commitments and refuse a different one from the server. Each trustee's browser checks the shares dealt to it as soon as the key is set up, and a bad share stops the vote from taking ballots. The audit file carries the commitments and proofs.
- Signed, versioned encrypted content. Doc versions and private-task text are signed with the writer's Ed25519 key, and doc ciphertext is bound to its version number. Content without a valid signature stays locked or read-only, and browsers warn when the server serves an older version of a doc than one they've opened.
- System notifications for private tasks say "A private task" instead of showing the decrypted title.

### Added

- Anonymous built-in AI requests. A member with a voting key sends AI requests without the session cookie, with a Semaphore proof that some current member asked, so the server enforces each member's daily allowance without learning who asked. Each request spends one of the day's slots (scope `nil/ai-credit/v1`, one per slot per UTC day), its proof is bound to the exact request, and nullifiers are kept with their day only and deleted when it ends. Admins switch it in Settings → Connect AI and see a count per day. Members without a key and guests send signed in, every AI button says which way its request goes, and [docs/ai-assistants.md](docs/ai-assistants.md#anonymous-requests) says plainly what it doesn't hide: in a small team the group is small, the server and Anthropic still read the request, and its words, its timing and its IP address can still point to a person. New settings: `AI_REQUESTS_PER_DAY` (100), `AI_REQUESTS_PER_MINUTE` (12, the limit that was fixed before), `AI_CREDIT_ROOT_MINUTES`, `AI_CREDIT_ROOTS`, `AI_CREDIT_PER_ADDRESS_PER_MINUTE` and `AI_CREDIT_USAGE_DAYS`. Migration 029 adds the nullifier, usage and member-list tables.
- Agents: AI teammates. Admins add agents in Settings → Agents with a name, avatar colour, description, instructions, projects, read or write access and a tool allowlist. Agents appear in the assignee and @mention pickers with an Agent badge, can be assigned tasks, mentioned and set to watch, never sign in and don't take a paid seat. Private tasks and docs stay out of their reach: they are encrypted, and a private task can't be assigned to an agent. Every change an agent makes is in the task history under its name, with who it acted for, and in its audit trail. Admins can pause or delete an agent, rotate its key, and switch every agent off at once. See [docs/ai-agents.md](docs/ai-agents.md).
- Changes an agent asks for outside its projects, deleting or cancelling, giving work to people or taking it from them, and bulk changes wait for an admin or the task's owner to approve them on an approval card in the timeline.
- External agents connect over MCP or a new REST API at `/api/agent/v1` with their own key, per-agent rate limits, idempotency keys and one error shape. The OpenAPI 3.1 document at `/api/agent/v1/openapi.json` is generated from the MCP tool list. New tools: `my_assignments`, `my_inbox`, `mark_inbox_read`, `search_tasks`, `list_labels`, `list_people`, `list_goals`, `claim_task`, `watch_task`, `delete_task`, `start_time_entry`, `stop_time_entry` and `get_approval`; `get_task` returns checklist item ids and `update_task` can add and tick checklist items and labels. These work with personal access keys too.
- Signed webhooks for external agents: `task.assigned`, `task.updated`, `comment.created`, `task.due_soon` and `approval.decided`, signed with HMAC-SHA256 over the timestamp and body, retried with backoff and jitter, with a delivery log, manual redelivery and automatic switch-off after repeated failures. Payloads carry ids and keys, never task text. Webhook and model addresses that resolve to private, loopback, link-local or metadata addresses are refused, and the checked address is the one connected to, unless `AGENT_ALLOW_LOCAL_ENDPOINTS` allows local ones.
- Built-in agents run inside Nil on Anthropic or on any OpenAI-compatible endpoint, including a local model. Assigning or mentioning one queues a run that reads the task, works through the same tools within step, token and time limits, comments on what it did, ticks finished checklist items and moves the task to In review. The queue survives restarts and retries transient errors. Each run's steps show in the task timeline, and Settings → Agents shows usage and a cost estimate per agent.

- Private tasks are end-to-end encrypted. A private task's title, notes, checklist and comments are sealed in the browser with a key only its creator and assignee hold (X25519 key wrapping and AES-256-GCM, the same scheme as docs). The server stores ciphertext and refuses plain text for a private task. Reassigning one seals it under a fresh key and re-encrypts its comments. Private tasks from before this change are sealed the next time their creator or assignee unlocks, and the plain copies the server kept (old titles in the history, notification previews, receipt titles) are wiped. The new-task box has a Private switch, so a private task is encrypted from its first save.
- Files on private tasks are encrypted too. Each file gets its own random key and is encrypted in the browser with AES-256-GCM, its name and type included, and that key is wrapped under the task's key. The server stores ciphertext under a generic name, serves it only as a download, refuses plain uploads to a private task and keeps file names out of its history. Reassigning a private task re-wraps the file keys only, never the files. Making a task with files private encrypts each one in the browser and swaps it in with the task, all or nothing, and opening a task up does the reverse. Migration 018 adds the column that holds each file's sealed details.
- AI assistants can't create private tasks and see encrypted ones only as placeholders.
- A help center inside the app, at `/help`. It shows the pages in `docs/`, bundled at build time, with a topic list and a search over titles and text. It opens from the question mark next to your name in the sidebar, from the account menu, from search (including "Search help for" with whatever you typed) and from the keyboard shortcuts dialog. Signed out, it's a public page linked from the sign-in screen. Small question-mark links next to private tasks, the Nil Pro notice, votes, docs, bounties, private payouts, AI settings, proof of work and data settings open the matching page.
- Markdown in task descriptions, comments and docs can now contain tables.
- A setup token guards a fresh server. Creating the first workspace, or restoring a capsule into an empty server, needs a one-time token: `SETUP_TOKEN`, or one the server makes at first start, prints once in the log and keeps in `DATA_DIR/setup-token`. The setup and restore screens ask for it. It stops working once a workspace exists, and erasing the workspace makes a new one.
- Clean shutdown. On SIGTERM or Ctrl+C the server stops its jobs, tells open tabs to reconnect (WebSocket close code 1001), lets requests in progress finish, waits for running jobs and closes the database, then exits 0. If that takes longer than `SHUTDOWN_TIMEOUT_SECONDS` (20) it exits with an error. `docker-compose.yml` allows 30 seconds.
- `/healthz` checks the database and answers 503 when it doesn't respond. It reports the version, the schema, when each job last succeeded and failed, and whether the Ethereum node answered the last time it was asked, and nothing about the workspace.
- A copy of the database before every upgrade. Before applying migrations, the server saves `pre-migration-<time>-schema-<n>.db` in the data folder with `VACUUM INTO` and keeps the newest three. Erasing the workspace deletes them too.
- `STRICT_CONFIG=1` refuses to start while any `[config]` warning remains. `LOG_FORMAT=json` writes one JSON object per log line.
- Settings for values that were fixed in code, with the old values as defaults: `NOX_RPC_TIMEOUT_SECONDS`, `NOX_MISSING_TX_HOURS` (bounty payments), `MAX_JSON_KB`, `NOTIFICATION_DAYS`, `USED_INVITE_DAYS`, `JOB_PURGE_SECONDS`, `JOB_PAYMENTS_SECONDS`, `JOB_VOTES_SECONDS`, `JOB_REMINDERS_SECONDS`, and new ones for `JOB_OPTIMIZE_SECONDS`, `DB_JOURNAL_LIMIT_MB`, `AI_TIMEOUT_SECONDS` and `AI_MAX_RETRIES`. All are in `.env.example`.
- Migration 019 adds indexes for the hourly purge (comments, activity and read notifications by date) and for tasks by creator. SQLite's `PRAGMA optimize` runs hourly, and the write-ahead log is cut back to 64 MB after checkpoints.
- Nil Pro is billed with invoices, priced in US dollars and paid in USDC or NOX. An admin picks the periods and people, sees the price line by line (flat fee `PLAN_PRICE_USD`, `PLAN_SEAT_USD` per person above `PLAN_FREE_SEATS`, staker discount, credit) and makes an invoice that asks for an exact amount of USDC at face value or of NOX at `PLAN_NOX_DISCOUNT` off. The NOX rate comes from a Uniswap V3 NOX/WETH pool's 30-minute average times Chainlink's ETH/USD feed, inside `PLAN_NOX_USD_MIN` and `PLAN_NOX_USD_MAX`, else the manual `PLAN_NOX_USD`, and is locked into the invoice.
- Every asked amount ends in a suffix that no other live invoice uses, and the server watches the treasury's incoming transfers for it, so a payment from any wallet, phone wallet or exchange finds its invoice. Hosts that run several workspaces on one treasury give each server a `PLAN_INVOICE_SLOT` and a shared `PLAN_INVOICE_KEY`: suffixes then come from each server's own share, shuffled so the public transfers don't link payments to a workspace, and one transfer can never pay two workspaces. Invoices show waiting, seen, confirming, underpaid (with the exact top-up), paid, overpaid (extra days in proportion), expired and cancelled. What an expired or cancelled invoice received becomes credit for the next one.
- The Plan screen pays from the browser wallet in one click, or by copying the exact amount, opening an EIP-681 link or scanning a QR code drawn in the browser by Nil's own encoder. It lists every invoice with explorer links and shows what the workspace paid the treasury next to the published burn share (`BURN_SHARE`, `BURN_REPORT_URL`).
- NOX perks. A workspace whose owner or an admin holds a Zero-State Pass gets Nil Pro (`PRO_FOR_ZSP`), checked every `PLAN_PERK_CHECK_HOURS` and whenever an invoice is made. Admins who stake NOX get a discount by tier (`PLAN_STAKER_TIERS`, `10000:10,100000:25` by default). Owners and admins are reminded 7 days and 1 day before Pro runs out (`PLAN_REMIND_DAYS`).
- A fairer token-holder door. NOX held, NOX staked and Zero-State Passes (each worth `HOLDER_ZSP_NOX`) count toward the minimum. Members who joined that way are checked at every sign-in, every `HOLDER_RECHECK_HOURS` and whenever someone new joins the same way, so the same NOX can't let several wallets in one after another. Falling below brings a notice and `HOLDER_GRACE_DAYS` of grace before they're signed out.
- Migration 020 adds the billing tables, the holder checks and payment intents, moves the paid-until date and past plan payments over, and drops `plan_payments`.
- Continuous integration (`.github/workflows/ci.yml`): tests, type check, build, `npm audit --omit=dev`, a Docker build that boots the image and checks `/healthz`, and an upgrade of a 3.0.0 database (`server/test/fixtures/v3.0.0.db`) to the latest schema.
- A tab notices a new deploy. The server tells open tabs which build it serves, and a tab running an older one shows "A new version of Nil is ready" with a Reload button. A tab that asks for a screen whose files a deploy removed reloads once by itself. An error no screen handles now shows a plain page with a Reload button instead of a blank one. Nothing about the error leaves the browser.
- Push notifications, opt-in per device. Settings → Notifications turns them on for the browser or phone you're using. Reminders, tasks assigned to you, mentions and tasks coming due then arrive even when Nil is closed. Each notification is encrypted for the device (RFC 8291) and signed with the server's VAPID key (RFC 8292), which is made on first start and kept in `DATA_DIR/keys`, or set with `VAPID_PUBLIC_KEY` and `VAPID_PRIVATE_KEY`. It travels through the push service of the browser's maker (Google, Apple, Mozilla, Microsoft), which can see that a notification arrived and when, but not what it says. Every notification is padded to the same size. A private task only ever sends "Reminder" or "A private task is due" with its id. A team task shows its title unless the device turns off "Show task names in notifications". Comment text is never sent. Signing out on a device stops its notifications. The server posts only to the hosts in `PUSH_SERVICES`, and `PUSH_NOTIFICATIONS=off` turns push off for everyone.
- Due times. A due date can have a time, set in the date picker and shown in lists, board cards, the calendar and the task drawer on each reader's own clock. It is stored in UTC together with the time zone it was set in, which stays on the server, so moving the date or repeating the task keeps the same wall-clock time across daylight saving changes. Reminders offer picks such as "1 hour before it's due".
- Due notes. "Due soon" goes out `DUE_SOON_MINUTES` (default 30) before a due time. For tasks due on a day without a time, each person gets one note at `DUE_DAY_HOUR` (default 9) on their own clock. Both appear in the inbox and as push notifications. `JOB_DUE_ALERTS_SECONDS` (60) sets how often the server checks.
- Quick add understands more. Times ("at 3pm", "5pm", "15:30", "noon"), days of the month ("on the 1st"), "in two weeks", and repeats such as "every 3 days", "every other week", "every monday" and "every month on the 15th". A time typed without a day means the next time the clock shows it.
- Repeat rules beyond the presets. A task can repeat every few days, weeks, months or years, or monthly on a day of the month, including the last. Rules are stored as a small subset of iCalendar's RRULE. A rule that says the same as a preset is stored as the preset, so older apps keep reading it.
- A personal calendar feed. Settings → Notifications makes a secret ICS link for Google Calendar, Apple Calendar or Outlook that lists your open assigned tasks with a due date. Private tasks appear only as "Private task", with no title, link or project. The link works without a cookie, is rate limited (`CALENDAR_FEED_PER_HOUR`), can be replaced or turned off at any time, and stops working when a member's access is removed. Settings warns that anyone with the link sees those tasks. The database stores only the feed's id; the link also carries a MAC made with a key kept in `DATA_DIR/keys`.
- Everyday team or crypto team. Setting up a workspace asks one question. An everyday team starts with bounties, votes, proof of work, private payouts and the token holder door hidden; a crypto team gets all of them. Admins can switch this in Settings, Workspace at any time, and nothing is deleted either way. With the tools off, their pages, menu entries and server routes are gone (the server answers 404), people go by name, and a wallet address shows only after a click on "Show wallet". The Nil Pro subscription works the same either way. Workspaces that existed before this keep their crypto tools on.
- Getting started. After setup, the owner's My work shows a short checklist: create a project, invite people, add a task with quick add, try a private task. Each step ticks itself when it happens, and the card can be dismissed. It also offers a sample project with a website launch, an offsite and a hiring round, which can be removed again in one click.
- Reusable invite links. Next to single-use links, admins can make a link several people can join through, with an expiry of 1, 7 or 30 days and an optional limit on how many. Links can be revoked, and admins see who joined through which link. Reusable links never make admins.
- Search by words. The command palette finds tasks by their notes, checklists and comments as well as their titles, and marks the matching words. Team tasks are searched on the server with SQLite full-text search, under the same visibility rules as the rest of the app. Private tasks and docs never go into that index: the browser searches the ones this tab has opened, in memory only.
- Import from Todoist, Trello or a CSV file. Settings, Data reads a Todoist project CSV, a Trello board JSON or any CSV with a header row in the browser, shows a preview, and lets you match its people and projects to this workspace. Tasks are then created a few at a time with progress, through the same calls the app uses everywhere. If you make them private, each one is encrypted in the browser from its first save.
- The calendar has an agenda on phones. Below 600px a compact month picks the day, that day's tasks sit underneath with an Add button, and the rest of the month follows. Every task has a Move button that opens the date picker, so rescheduling works without dragging.
- The board has column tabs on phones, and cards on touch screens have a Move button that changes their column without a drag.
- The task panel has a Mark complete button, which reads Reopen on a finished or canceled task.
- Search is one tap from the top bar whenever the sidebar is folded away.
- Every wallet in the browser is found. Nil now finds installed wallet extensions through EIP-6963. With more than one, it asks which to use, showing each wallet's own name and icon, and remembers the choice on that device. Wallets that only set `window.ethereum` still work.
- Help for people without a wallet. Signing in on a device with no wallet now explains what a wallet is, why Nil uses one, and that signing in costs nothing and sends nothing. Computers get links to a few wallets' official sites and a QR code that opens the same page on a phone. Phones, including iPhone Safari and the installed app, get "Open Nil in your wallet app" links for MetaMask, Coinbase Wallet, Rainbow and Trust Wallet. Nil loads nothing from these wallets, and the QR code is drawn in the browser.
- Smart-contract wallets can sign in, including passkey wallets such as Coinbase Smart Wallet. Plain wallets are still checked first, without asking the Ethereum node. Other signatures are checked on the configured chain with EIP-1271, or EIP-6492 for a wallet that isn't deployed yet, within `SIGNIN_CHAIN_TIMEOUT_SECONDS` (8). Bounty applications accept them too. Signed ballots in votes still need a plain wallet.
- Reset sign-in. In Settings → Team, an admin can reset the sign-in of someone who lost every wallet. The link works once, expires after `SIGNIN_RESET_HOURS` (24), lets that person link a new wallet to the same account with the same history, tasks and role, and signs them out on every other device. Their old wallets can then be removed. Resetting an owner needs a second admin to approve when there are two or more other admins. With only one, that admin has to confirm a clear warning first. Every step, and every wallet linked or removed, goes into a sign-in history that keeps account ids only, never links or addresses. Migration 025 adds its two tables.
- Right after sign-up, and in Settings → Sign-in & security while you have only one wallet, Nil suggests linking a backup.

### Changed

- Built-in AI has a daily limit per person (`AI_REQUESTS_PER_DAY`), signed in or not. While anonymous requests are on, a member with a voting key can't also send signed-in ones, so nobody gets two allowances.
- The voting key can be registered with the crypto tools off, since it also sends AI requests anonymously.
- A status deck's AI request leaves private tasks out, even when they're on the slides. The task AI buttons are hidden on private tasks.
- Big workspaces start fast. The app starts with open work and recent history as cards: title, status, dates, labels and checklist progress. Notes and checklists load when a task is opened. Finished tasks nobody has touched in 30 days stay on the server until a view needs them: All tasks and project lists have a Load older button, the calendar fetches finished tasks due in the month on screen, Insights and status decks load the weeks they cover, and search looks through them too. Goal and project progress still counts every finished task, and a finished task with an unpaid bounty always loads. `RECENT_CLOSED_DAYS` (30) and `RECENT_CLOSED_MAX` (1000) set how much history comes up front. On a test workspace of 20,000 tasks, the first load went from 30 MB and 0.9 s of server time to 3.5 MB and 0.14 s.
- A private task starts as its encrypted title and checklist; its encrypted notes arrive when it's opened.
- Tabs reconnecting after a server restart spread their refresh over a few seconds instead of all asking at once.
- Smaller app download. Settings, Docs, Votes, Bounties, Proof of work, Verify, Insights, Calendar, Goals, Time, sign-in and the public pages load the first time they're opened, and the cryptography for private tasks and payouts loads on first unlock. The code needed to start went from 612 kB to 414 kB (193 kB to 130 kB compressed). Libraries sit in files of their own that stay cached, so most deploys only change a 184 kB file.
- The Caddyfile in `docs/deploy.md` compresses responses with `encode zstd gzip`. Add that line to yours.
- API: `GET /api/bootstrap?tasks=cards` returns task cards and an `archive` section, and `GET /api/tasks/archive` and `/api/tasks/archive/summary` page through older finished tasks. Plain `GET /api/bootstrap` still returns every task in full, for tabs opened before this release and for scripts. Every task now carries `steps`, its checklist progress.
- Live updates are encoded once for everyone who gets the same one, instead of once per open tab.

- The app is now called Nil. NØNOS stays as the name of the foundation behind it. The app shows the Nil lockup (the official Ø mark with letters drawn from the same Geist cut as the NØNOS wordmark, see `scripts/brand/nil-wordmark.py`), and its title, install name, sign-in page and messages say Nil. The paid plan is called Nil Pro. Messages your wallet signs to derive keys are unchanged, so every existing key still works.
- New workspaces start with an empty name instead of NØNOS.
- The documentation is split into short pages in `docs/`, one topic each, with `docs/README.md` as the index. The README is now a short front page. `docs/DEPLOY.md`, `docs/TOR.md`, `docs/PROOFS.md` and `docs/ZERO-STATE.md` became `docs/deploy.md`, `docs/tor.md`, `docs/proof-format.md` and `docs/zero-state.md`.
- The Docker build copies `docs/`, which the in-app help is built from.
- `docker-compose.yml` publishes port 3000 on 127.0.0.1 only. Put Caddy or another TLS proxy in front, as `docs/deploy.md` describes. It also limits the container to 1 GB of memory (2 GB in memory-only mode, whose data lives in RAM) and rotates its logs.
- The Docker image is pinned to Node 22.23.3 on Alpine 3.24 by digest, carries OCI labels with the version, and its health check follows `PORT`.
- Log lines carry a timestamp and a level. Configured secrets are cut out of every line, and request bodies, cookies and headers are never logged. The startup line shows the version and `APP_URL`.
- Stricter settings checks. `NOX_TOKEN`, `REWARD_TOKENS`, `STEALTH_ANNOUNCER`, `NOX_STAKING`, `ZSP_CONTRACT` and `PLAN_TREASURY` must be valid addresses, with a correct EIP-55 checksum when they mix upper and lower case; a bad one is named in a warning instead of being dropped quietly. With `NOX_CHAIN_ID` other than 1, the contracts have to be named, since the defaults are mainnet contracts. `NOX_CONFIRMATIONS` is at least 1. In production the server warns about an empty `APP_URL`, an https `APP_URL` without `TRUST_PROXY`, and the default public Ethereum node.
- An AI request gives up after 120 seconds and is retried once, instead of the SDK's default ten minutes and two retries.
- Every token payment counts only once its block is finalized, read with the `finalized` block tag, or `NOX_FINALITY_DEPTH` (64) blocks under the head on nodes without it. Each payment keeps its block hash, and a reorganisation that moves or drops it before then is followed. `NOX_CONFIRMATIONS` is no longer read.
- Bounty payments start in Nil. It gives the exact amount still owed, ending in digits that identify the payment, and only a transfer mined after that, from the payer's wallet or a treasury address, to the contributor, carrying those digits, counts. One transaction pays exactly one thing: a bounty or an invoice, in one task and one workspace. Recording the same transaction twice changes nothing. Underpayments count as part of the bounty, which offers to pay the rest; overpayments still pay it. A payment stuck before it is mined can be cancelled and paid again, and is watched for `PAYMENT_WATCH_DAYS` in case it lands anyway. Payment endpoints are rate limited. Paying from a Safe first shows the exact amount to send, valid for `PAYMENT_INTENT_DAYS`.
- Private payout announcements also count only at a final block. The browser checks that the address Nil names for a payout is the one it expects before sending anything.
- The trial starts once per server, and its last grace days are part of `PLAN_TRIAL_DAYS`, so trial and grace together last exactly that long. Erasing the workspace keeps the billing record (without who paid), and restoring a capsule brings none of it, so neither can start a new trial or replay a payment.
- With paid Pro, a team can have as many people as it paid for; seats can be added for the rest of the paid time. A plan paid before this change covers the people the workspace had when it was upgraded. Letting someone back in or making a guest a member takes a seat too.
- Wording names the treasury as `PLAN_TREASURY_NAME` (default "the treasury"). `PLAN_PRICE` is no longer read and says so at startup.
- The server refuses to start on a database written by a newer release, and says so, instead of running against a schema it doesn't know. A capsule from a newer release is refused the same way.
- Desktop notifications moved from Settings → Profile to the new Settings → Notifications.
- A reminder about a private task no longer keeps the task's title in the stored notification.
- Migration 022 adds the crypto tools switch, invite use counts and the search index. Wiping the workspace and restoring a capsule now leave the index's own tables alone and rebuild it from the tasks.
- Unused invite links are still deleted as soon as they expire. Links someone joined through are kept for `USED_INVITE_DAYS` (30) days after they end, so admins can see who came in with them.
- On touch screens every control is at least 44 by 44 pixels: list checkboxes, status icons, Mark as done, My Day, header and panel buttons, filter chips and tabs. Small icons keep their size and get a larger invisible hit area, so desktop looks the same.
- Text fields are 16px on touch screens, so iOS no longer zooms in when one takes focus.
- Faint text is darker (4.97:1 on white instead of 3.16:1), and the backlog, canceled and in-progress status icons clear 3:1. Body text is at least 13px; only metadata such as dates, keys and counts uses the 12px size.
- Icon buttons in the task panel and the docs toolbar show their names as tooltips with a mouse. On touch and narrow screens the task panel prints the names under its tools, and the docs toolbar moves history, download and print into a menu with Delete set apart at the bottom.
- Unassigned tasks show an outlined assign icon instead of a dashed question mark.
- Initials on light member colours (ochre, teal, moss, sky, persimmon) are ink instead of white, which was as low as 3.25:1.
- Filter chips that run past the edge of a phone screen end in a chevron that scrolls them on.
- The comment box only mentions Ctrl+Enter where there is likely a keyboard.
- The sign-in screen uses plain words. It no longer mentions gas or on-chain checks, and "Hold NOX? Join without an invite" now reads "Have NOX tokens? Join without an invite".

### Fixed

- A long hint in a menu could squeeze the item's label to nothing. Hints now give way and trail off first.
- A background job that failed, for example on "database is locked" or a full disk, could take the whole server down. Every job now logs its failure (at most once every ten minutes while it keeps failing) and runs again on schedule. Errors in the live-update connection are caught the same way, and an error nothing else handles stops the server cleanly instead of abruptly.
- Payment checks that failed were dropped without a word. They are logged now, rate-limited.
- A missing file under `/assets/` got the app's HTML with status 200. It is a plain 404 now.
- A capsule export kept encrypting after the browser cancelled the download. It stops now, and its plaintext database snapshot is always deleted.
- After a deploy, the service worker could store the app's page in place of a script that no longer existed, which broke that screen until the browser's cache was cleared. It now stores only real build files. While the server restarts, an installed app opens from its stored copy instead of an error page.
- A long explanation next to a switch in Settings could push the switch out of its card. The words wrap now.
- Settings scrolled sideways on phones (up to 929px wide on Team), and long switch descriptions were cut off on desktop. My work's side column could also push the page wider than the screen.
- The task panel now keeps keyboard focus inside while it is open and returns it to where it was on close. Dialogs share the same code, and no longer move focus each time they re-render.
- The task title, checklist steps, the My work add field and text inputs show a clear focus ring.
- A My work row and a board card were buttons with other buttons inside, and Space did nothing on a row. Their controls are now separate buttons. Pressing Enter or Space on a button inside a card no longer starts a keyboard drag.
- The closed sidebar on narrow screens could still be reached with Tab.
- The docs delete button and the command palette's results list had no accessible name.
- A workspace without a name showed "Sign in to" with nothing after it, and asked wallets to sign "Sign in to ." Both now say Nil.

## 3.0.0 (2026-10-15)

Version 3 makes the Ethereum wallet the only way in and adds NOX token utility: bounties paid on-chain, private payouts, token-weighted and anonymous votes, and an optional NOX subscription. It also adds encrypted docs, everyday tools, sharing, an MCP connection for AI assistants and PowerPoint decks.

### Breaking changes

- Wallet-only sign-in. Email, passwords and passkeys are gone. Sign-In with Ethereum is the only way in. Migration 004 rebuilds the users table without email or password columns and deletes every non-wallet sign-in method. Before upgrading from v2, every person must link an Ethereum wallet. See [docs/deploy.md](docs/deploy.md#11-upgrades).
- Light interface only. Dark mode is removed.

### Added

**Bounties and payouts**

- Bounties on tasks, paid by an admin's own wallet straight to the contributor. The server only reads the chain: it checks the token contract, sender, receiver and amount after enough confirmations, then signs a payment receipt that joins the contributor's proof of work. Pending payments are re-checked every minute.
- A Bounties page: open bounties, amounts promised, owed and paid per person and token, payment history and treasury addresses (for example a Safe multisig) that may also pay.
- Bounties in NOX or USDC. Each task carries its reward token, payments are checked against that token's contract, and totals, receipts, decks, notifications and MCP output show each token separately. `REWARD_TOKENS` configures the list. NOX is always first and USDC on mainnet is the default extra.
- Private payouts to ERC-5564 stealth addresses. Stealth keys come from one deterministic wallet signature and live only in the browser tab. Each payout goes to a fresh one-time address, is announced on the standard announcer and carries a small ETH top-up for gas, in one atomic EIP-5792 batch where the wallet supports it. The server confirms the payout reached the payee's stealth address. Payees can see balances, move funds from the browser or export the key. Derivation matches the ERC-5564 reference SDK on pinned test vectors.
- A public bounty board at `/open`, also published as `/.well-known/nonos-bounties.json`. Outsiders apply by signing a message with their wallet, with no account or email. Accepted applicants become guests who see only their task.

**Votes and membership**

- Votes signed by the voter's wallet, counted one per person or by voting power. Results can be sealed until the vote closes. Admins can download a recount file.
- A token-holder door: admins can let anyone holding a minimum of NOX join as a member. For people who joined that way, the balance is checked again at every sign-in.
- Voting power = NOX in linked wallets + NOX staked in the official staking contract + Zero-State Passes × a power per ZSP that admins set (`VOTE_ZSP_POWER` is the default). It is read for every member at one block when a weighted vote opens, so tokens moved during the vote can't count twice and people who join later have no power in it. The recount file carries the block, the contracts and every member's breakdown.
- Anonymous votes with Semaphore zero-knowledge proofs. Each member's voting key is derived from a wallet signature, and only its public commitment reaches the server. Ballots are proven in the browser from circuit files the server hosts, sent without the session cookie, and limited to one per member per vote. The recount file holds every root and proof but no names. `npm run zk:fetch` downloads circuit files for other tree depths and keeps them only if they pass hash and proof checks.
- Beta: encrypted weighted anonymous votes with three trustees. A new circuit (`circuits/ballot.circom`, 30,669 constraints) proves the voter is in the vote's census with their snapshotted power and encrypts that power into the chosen option with exponential ElGamal on Baby Jubjub. Trustees run a distributed key generation, so nobody holds the private key. After the vote closes, any two trustees decrypt only the totals, with Chaum-Pedersen proofs. The circuit has not been audited, and its Groth16 phase 2, recorded in `circuits/CEREMONY.json`, is a development ceremony run on one machine. It must be rerun with independent contributors before these votes are relied on. `npm run zk:ballot` rebuilds the circuit and setup.

**Subscription**

- An optional NOX subscription. A workspace pays NOX from an admin's wallet or a treasury address to the operator's treasury, and the server adds one period per full price after checking the transfer on-chain. Nothing is charged automatically.
- Paid tools: new bounties and public listings, opening new votes, the token-holder door, built-in AI, the MCP connection, and teams beyond the free seats. Reading, exporting, paying bounties already promised and finishing votes already opened (ballots, closing and trustee decryption) are never gated.
- A free trial counted from workspace setup, a grace period after a lapse, and community mode (everything unlocked) when `PLAN_TREASURY` is not set.
- Settings → Plan: status, price, seats, paying 30 to 360 days from a wallet or by pasting a multisig transaction, and payment history.

**Everyday work**

- Private tasks, visible only to their creator and assignee, not even to admins.
- Personal time tracking with a timer, a private timesheet and CSV export.
- Reminders that arrive as notifications.
- An installable progressive web app. Its service worker never caches API data.

**Docs, sharing and AI**

- End-to-end encrypted docs. Keys are derived in the browser from a deterministic wallet signature over a message that names the workspace by its signing key, so renaming the workspace doesn't change anyone's keys. Private payout and voting keys work the same way. Every doc has its own AES-256-GCM key sealed per reader. The server stores only ciphertext, keeps 25 encrypted revisions, refuses stale saves and re-keys a doc when a reader is removed. Online teammates hand team docs to newcomers automatically.
- Project guests, member invites (when admins allow them) and read-only share links. Share links are off until an admin enables them, stored as hashes, expiring and revocable, and show no people, comments, files, addresses or private tasks.
- An MCP endpoint at `/mcp` for AI assistants, authenticated by personal access keys that are shown once, stored as hashes, scoped read or read-write, expiring and revocable. Eight tools run through the same visibility rules as the app.
- Draft with AI in docs, with a plain notice of what leaves the browser.
- One-click PowerPoint status decks for the workspace, a project or a goal, built in the browser, with speaker notes. With AI on, Claude can write the summary and notes from the facts on the slides.

**Other**

- The official NØNOS brand: logo, mark and icons, Geist and JetBrains Mono, and motion that turns off under reduced motion.
- `marketing/video`: a kit that renders marketing videos in code. It is not part of the app or the Docker image.

### Changed

- Tests are split into identity, tasks and data suites, with new suites for bounties, holders, votes, anonymous and encrypted votes, docs, sharing, plan, stealth payouts and MCP.
- Polish to the bounty field, the timesheet layout and list rows on phones.
- The Content Security Policy adds `'wasm-unsafe-eval'` so the browser can run the zero-knowledge prover. It still allows no JavaScript `eval` and no other hosts.
- Settings: an empty value counts as unset everywhere, so the default applies. A number, `PLAN_TREASURY`, `PLAN_PRICE` or `NOX_EXPLORER` that can't be used is named in a startup warning instead of silently changing how the server behaves.
- Block-explorer links on the proof verifier use `NOX_EXPLORER`.

### Security

- Patched security advisories in express, ws and vite. Transitive ws, snarkjs and underscore are pinned to patched versions.
- Docker builds leave out local data folders, databases, capsules, exports, `.env` files and keys wherever they sit in the tree, and the Dockerfile removes any that slip into the server folder before the runtime image is assembled.

### Known limits

- No part of NØNOS's own code has had an independent security audit.
- Encrypted weighted votes are beta, for the reasons above.
- See [Honest limits](docs/privacy-model.md#honest-limits) in the privacy model.
